# 022 対象月入力の yyyymm 対応設計

## 要望

- 対象機能:
    - 「指定の月に自分の勤怠を詰め込む」
    - 「指定の月の自分の勤怠をリセットする」
- 対象月の入力で `yyyy-mm` に加えて `yyyymm` も受け付けます。
- プロンプトを `対象月を入力してね (yyyy-mm yyyymm どっちか): ` へ変更します。
- 背景: 2026-09 の登録で `202609` と入力され、フォーマット不正で終了コード `2` になった事例がありました。 freee への書き込みは発生していませんでした。

## 現状

- 登録側 `app/actions/bulk_attendance.py` と、リセット側 `app/actions/bulk_attendance_reset.py` に、同じ内容の `_parse_target_month` が重複していました。
- どちらも `re.fullmatch(r"\d{4}-\d{2}", raw)` で `yyyy-mm` のみを受け付け、 `datetime.strptime(raw, "%Y-%m")` で年月の妥当性を確認していました。

## 詳細設計

- 新規モジュール `app/actions/target_month_input.py` へ対象月入力を共通化します。
    - #22 で `hr_user_context.py` へ共通化した方式に合わせます。
- 公開する要素:
    - `TARGET_MONTH_PROMPT`: `対象月を入力してね (yyyy-mm yyyymm どっちか): `
    - `parse_target_month()`: `input()` で受け取り、前後の空白を除去して `parse_target_month_value()` へ渡します。
    - `parse_target_month_value(raw)`: `(year, month)` または `None` を返します。
- 入力仕様:
    - 受け付ける形式は `^(\d{4})-?(\d{2})$` です (`re.ASCII`) 。つまり `2026-09` と `202609` の 2 形式だけです。
    - `2026/09` 、 `2026-9` 、 `20269` 、 `2026-09-01` などはフォーマット不正です。
    - 月が `01` から `12` の範囲外、または年が `0000` の場合は「存在しない年月」です。 `datetime(year, month, 1)` の `ValueError` で判定します。
- エラーメッセージ:
    - 空入力: `[エラー] 入力が空です。` (変更なし)
    - フォーマット不正: `[エラー] フォーマットが不正です: '...'  (例: 2026-03 または 202603)`
    - 存在しない年月: `[エラー] 存在しない年月です: '...'` (変更なし)
- 終了コード: 不正入力時は従来どおり `EXIT_CODE_MENU_ERROR=2` です。 API 呼び出しの前に終了します。
- 各アクションは共通の `parse_target_month()` を呼び、ローカルの `_parse_target_month` を削除します。

## テスト観点

- `tests/test_target_month_input.py`
    - `2026-09` と `202609` が `(2026, 9)` になること
    - 1 月と 12 月の境界値を両形式で受け付けること
    - 空入力、フォーマット不正 (全角数字を含みます) 、存在しない年月でそれぞれのメッセージを出して `None` になること
    - プロンプト文言と前後空白の除去
    - 登録とリセットの両 handler で、不正入力時に `HrApiClient` を生成せず終了コード `2` になること
    - 両 handler で `202609` が year=2026 、 month=9 として後続処理へ渡ること (API はモックします)

## 制約

- 全角数字は `re.ASCII` で受け付けません。従来も `strptime` で弾かれていたので、受け付けない挙動を維持します。メッセージは「存在しない年月」から「フォーマット不正」へ変わります。
- `docs/agent` の過去の設計書にある `yyyy-mm` の記述は、当時の記録として更新しません。
